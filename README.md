> 一只常驻桌面的宠物，帮你在信息出现的瞬间把它记录下来，再交给 AI 整理成任务、摘要和可复习的知识。

Desktop Record Pet 把「记录」这件事做得尽可能轻：一只透明置顶的小宠物常驻桌面，配合全局快捷键，随时唤起快速输入或区域截图，把文字、图片、文件统一收进本地 SQLite。记录可以一键转为待办，待办支持分类、优先级、截止日期、重复规则和拖拽排序。接入 Anthropic、OpenAI、DeepSeek、Ollama 或其他 OpenAI-compatible 服务后，还能让 AI 为记录生成摘要、标签、行动建议，并围绕已有笔记和待办进行对话。

项目的核心不是“再做一个笔记应用”，而是把零散记录持续沉淀成属于个人的知识库，并连接三个瞬间：

**捕获**：降低记录文字、截图和文件的阻力。
**行动**：把值得处理的记录转成带截止日期和提醒的任务。
**沉淀**：让 AI 基于已有记录提炼知识点、归纳主题、发现关联，并逐步形成可理解、可检索、可复习的个人知识库。

除 AI 请求外，记录、附件、任务和知识记忆都留在本地机器上，不依赖云端账户或服务端数据库。

## 功能特性

### 桌面宠物

透明置顶常驻桌面、不占任务栏的小家伙。拥有待机动画（眨眼、左顾右盼）与光晕投影，可以随意拖拽到屏幕任意位置，重启后自动恢复。左键打开主面板，右键唤出快捷菜单。

### 快捷记录

通过全局快捷键随时唤起一个极简输入框，随手记下一笔文字。除文本外，还支持多种来源的记录捕获：内置区域截图、拖拽文件、剪贴板粘贴图片、文件选择器。每条记录可归类为笔记、任务、经验、问题或文件笔记，并可一键转为待办。

### 截图捕获

全局快捷键进入全屏区域选择，框选屏幕任意区域截图。截图完成后可补充文字说明，自动保存为带图片附件的记录。附件以文件哈希去重，避免重复存储。

### 记录管理

主面板提供全部记录的浏览、过滤与搜索。可按类型、状态或关键词筛选，查看记录详情时会聚合展示其附件、关联任务与 AI 分析结果。支持编辑、归档与删除。

### 待办管理

一个桌面常驻的浮层式待办列表，随时可见。任务有四种状态（待办 / 进行中 / 完成 / 取消）和三级优先级，可设置截止日期、提醒（宠物气泡或系统通知两种渠道）以及重复规则（每天 / 工作日 / 每周指定星期）。支持拖拽排序与分类夹管理，分类夹本身也可重排。

### AI 增强

在设置中可以创建任意多个 AI 配置，为每个配置设置独立名称、Provider、API key、地址和模型，并在聊天时自由切换。当前支持 Anthropic、OpenAI、DeepSeek、Ollama、OpenAI-compatible 自定义地址以及 OpenCode Zen 等配置方式。

对任意记录发起分析后，AI 会根据记录文本和图片返回结构化的摘要、标签、建议任务、研究洞察与敏感度标记，并存回记录详情。学习教练会把知识点、证据和掌握状态关联起来，支持基于原始记录继续追问。

### 宠物对话

- 支持独立的对话历史，可新建、打开、编辑标题、删除和批量删除对话。
- 首次发送消息时先生成本地临时标题，再异步使用 AI 优化标题；AI 失败时保留本地标题。
- 推荐相关笔记和待办，但不会自动加入上下文；只有用户点击推荐或手动勾选后才会引用。
- 已选引用会高亮显示，发送时只携带用户明确选择的内容。
- 支持宠物主动开场；主动回复会进入对话历史，但不会暴露内部提示词。
- 回复会以渐进方式显示，减少等待完整结果时的突兀感。

### 个人知识图谱（实验功能）

- 提供一个可缩放、可拖拽的二维知识地图，当前内置 Python 示例知识结构。
- 支持新建、编辑、删除知识点，修改描述、学习状态和官方文档链接。
- 支持建立“包含 / 相关 / 前置 / 应用于”等关系，并通过颜色区分未接触、已记录、学习中、已掌握和待复习状态。
- 支持把已有笔记和待办关联到知识点，点击知识点即可回看相关内容。
- 提供“知识库建议箱”：基于记录中已有的 AI 学习分析，自动推荐关联已有知识点或创建新知识点；用户确认后才会写入图谱，忽略的建议会被记住。
- 支持用户创建官方知识结构中不存在的自定义知识点。
- 支持以 JSON-LD 形状导入和导出，作为未来 Python、Git、Docker 等领域知识包的基础。

### 全局快捷键与设置

快速捕获和截图快捷键设计为可在设置面板中自定义，修改时会进行冲突检测并即时生效。设置面板同时管理 AI Provider、模型、API 地址和 API key 等配置项，支持一键重置。

## 隐私与数据

- 记录、任务、标签、知识记忆和附件保存在本地 SQLite 与附件目录中。
- 默认不需要登录，也没有内置云端同步或遥测服务。
- 只有在主动使用 AI 功能时，相关记录内容和图片才会发送到你配置的 AI 服务。
- API key 不会通过设置列表直接返回到前端；使用自定义 Provider 时，请确认对应服务的隐私政策和数据保留规则。

## 当前版本

项目目前处于早期开发阶段（`v0.1.0`），主要在 Windows 上开发和验证。当前版本已经完成一条可用的核心闭环：

```text
桌面捕获 → 本地保存 → 整理为笔记 / 待办 → 提炼知识点 → 建立知识关联 → AI 对话与复习
```

当前版本适合：

- 想尝试本地优先记录和桌面宠物交互的人；
- 想使用自己的 AI API key，并在多个模型之间切换的人；
- 想参与一个正在快速迭代的 Tauri + React + Rust 开源项目的人。

当前仍属于开发中版本，数据模型、交互和跨平台行为可能发生变化。建议重要数据定期备份，不要把它当作已经稳定的生产级知识库。

## 未来路线图

这个项目未来希望从“桌面上的记录入口”成长为一个本地优先的个人知识库系统：信息出现时由宠物帮你收下，之后从长期积累的记录中提炼知识、梳理关系，帮助你判断是否需要行动、何时复习，以及怎样重新找到相关内容。

计划中的方向包括：

- **更自然的捕获**：系统级选中文本、一键收图、文件和剪贴板内容的统一入口。
- **更可靠的整理**：让 AI 在用户确认后生成笔记、拆分任务、补充截止日期和提醒，而不是擅自修改本地数据。
- **更完整的个人知识库**：从长期积累的笔记、截图、文件和待办中提炼稳定的知识点、主题和经验，形成属于用户自己的可检索知识库。
- **官方知识包与个人副本**：以官方知识结构作为可选骨架，用户拥有自己的副本，可以修改、拆分、合并、删除和重新组织所有内容，也可以创建没有官方版本的自定义知识点；同时保留恢复官方版本的能力。
- **知识关系图谱**：识别知识点之间的关联、依赖、冲突和演化关系，以图谱形式展示个人知识结构，并支持从一个知识点回溯相关记录。
- **更强的对话记忆**：基于用户明确选择的笔记、待办、知识点和历史对话提供可追溯回答，并支持引用来源回看。
- **真正的流式对话**：接入 Provider 的原生 SSE / token 流，支持停止生成、重新生成和重试。
- **复习与知识形成**：从零散记录中提炼主题、关联证据，提供低压力的间隔复习和主动提醒。
- **更有生命感的宠物**：支持上传图片生成或配置宠物形象，增加表情、动作、语音和可自定义人格。
- **知识图谱组件生态**：将成熟的领域知识图谱封装为可浏览、导入和复用的市场组件，未来探索社区分享、付费交易和插件化扩展。该方向只作为长期规划，当前版本不会实现市场或交易功能。
- **更完整的数据能力**：导入、导出、备份、迁移，以及可选的端到端加密同步。
- **更广的平台支持**：完善 macOS / Linux 适配，并持续优化窗口、快捷键和通知体验。

路线图不是承诺的发布时间表，欢迎通过 Issue 分享真实使用场景，帮助确定优先级。

## 架构设计

### 多窗口架构

应用由 6 个独立窗口组成，通过 URL 参数 `?window=` 路由到各自的前端入口，各自拥有独立的生命周期与可见性控制：

| 窗口                   | 职责           | 特性                   |
| ---------------------- | -------------- | ---------------------- |
| `pet`                | 桌面宠物本体   | 透明、置顶、跳过任务栏 |
| `quick-input`        | 快速文本输入   | 置顶、按需唤出         |
| `screenshot-overlay` | 全屏区域截图   | 全屏透明覆盖层         |
| `supplement-box`     | 截图后补充说明 | 置顶、按需唤出         |
| `main-panel`         | 记录管理主界面 | 默认隐藏，点击宠物打开 |
| `todo-overlay`       | 待办浮层       | 透明置顶、可缩放       |

### 全链路数据流

一个功能从用户操作到落库，典型路径为：

```
用户操作 → React 组件 → Zustand store → lib/tauri.ts 封装
       → Tauri 命令(commands.rs) → db.rs(SQL) → SQLite
       ← data-changed 事件广播 ← 命令返回 ← store 更新 ← 组件重渲染
```

写操作完成后，后端通过 `data-changed` 事件广播变更，各窗口的 store 监听后自行刷新，保证多窗口间状态一致。

### 目录结构

```
desktop-record-pet/
├── src/                       # 前端
│   ├── assets/                # 品牌图标与前端静态资源
│   ├── components/
│   │   ├── capture/           # 快速输入、截图覆盖层、补充框
│   │   ├── panel/             # 主面板、记录列表、记录详情
│   │   ├── pet/               # 桌面宠物本体与右键菜单
│   │   ├── settings/          # 设置面板
│   │   └── todo/              # 待办浮层、分类、拖拽排序
│   ├── store/                 # Zustand 状态（records/tasks/settings/...）
│   ├── lib/tauri.ts           # Tauri 命令前端封装
│   ├── types/                 # TypeScript 类型定义
│   └── App.tsx                # 多窗口路由入口
├── src-tauri/                 # Rust 后端
│   ├── src/
│   │   ├── commands.rs        # Tauri 命令层（校验 + 广播）

│   │   ├── windows.rs         # 窗口生命周期 / 可见性
│   │   └── models.rs          # 数据模型与序列化
│   ├── capabilities/          # Tauri 权限配置
│   ├── icons/                 # 应用图标
```

## 快速开始

### 环境要求

- Node.js（建议 18+）
- Rust 工具链（stable，含 cargo）
- 系统依赖参见 [Tauri 2 前置要求](https://v2.tauri.app/start/prerequisites/)
- 主要在 Windows 上开发与测试

### 开发运行

```bash
# 安装前端依赖
npm install

# 启动开发模式（同时拉起 Vite 与 Tauri 窗口）
npm run tauri dev
```

### 构建打包

```bash
# 类型检查 + 前端构建 + Rust 编译，输出安装包
npm run tauri build
```

构建产物位于 `src-tauri/target/release/bundle/`。

### 验证命令

日常开发中可用于检查两端的命令：

```bash
# 前端类型检查与构建
npm run build

# Rust 编译检查
cargo check --manifest-path src-tauri/Cargo.toml

# 运行前端测试
npm test -- --run

# 运行 Rust 测试
cargo test --manifest-path src-tauri/Cargo.toml
```
